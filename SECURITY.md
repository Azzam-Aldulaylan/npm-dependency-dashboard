# Security Policy

## Supported versions

Security fixes are provided for the latest published stable version. Before the
first Marketplace release, the current `main` branch is the supported code line.

## Reporting a vulnerability

Please use GitHub's private vulnerability-reporting flow from the repository's
**Security** tab. Include the affected version or commit, a minimal reproduction,
impact, and any suggested mitigation. Do not include registry credentials,
private package names, source code, or other secrets that are not required to
reproduce the issue.

If private vulnerability reporting is unavailable, open a public issue asking
the maintainer to establish a private contact channel, but do not disclose the
vulnerability details in that issue.

You should receive an acknowledgement after the maintainer reviews the report.
Timelines for validation, remediation, and disclosure depend on severity and
release risk and will be coordinated through the private report.
